# শপবাজার — মাল্টি-ভেন্ডর মার্কেটপ্লেস (React)

React 19 · Vite 7 · Tailwind CSS 4 · React Router 7

এক অর্ডারে একাধিক বিক্রেতার পণ্য — সেই কাঠামোর উপর দাঁড়ানো একটা সম্পূর্ণ
মার্কেটপ্লেস ফ্রন্টএন্ড। এখন ব্যাকএন্ড ছাড়াই চলে (ব্রাউজারের ভেতরের mock ডেটা দিয়ে),
পরে `.env`-এ একটা ফ্ল্যাগ বদলালেই Django REST API থেকে ডেটা আসবে।

## ১. চালু করা

```bash
npm install
npm run dev
```

খুলুন <http://localhost:5173>

```bash
npm run build     # প্রোডাকশন বিল্ড → dist/
npm run preview   # বিল্ড করা সাইট দেখা
npm run lint      # ESLint — বাগ ও অব্যবহৃত কোড ধরার জন্য
npm test          # Vitest — ২৭টি টেস্ট (টাকার হিসাব)
npm run test:watch  # ফাইল বদলালেই আবার চলবে
```

> `src/lib/pricing.test.js` ব্যাকএন্ডের `backend/tests/test_pricing.py` এর
> আয়না। দুই জায়গার নিয়ম এক না থাকলে ক্রেতা কার্টে এক টাকা দেখবেন,
> চেকআউটে আরেক — তাই একটা বদলালে অন্যটাও বদলাবেন।

## ২. কী কী আছে

**ক্রেতার সাইট**

- হোম — ব্যানার স্লাইডার, ক্যাটাগরি, কাউন্টডাউনসহ ফ্ল্যাশ সেল, জনপ্রিয় দোকান, সম্প্রতি দেখা
- পণ্যের তালিকা — সার্চ, ক্যাটাগরি/দাম/রেটিং/দোকান ফিল্টার, সর্টিং, পেজিনেশন (সব URL-এ থাকে)
- পণ্যের পাতা — গ্যালারি, ভ্যারিয়েন্ট (সাইজ/রঙ) পিকার, স্টক, রিভিউ ব্রেকডাউন, একই ধরনের পণ্য
- দোকানের পাতা — ব্যানার, রেটিং, ওই দোকানের সব পণ্য
- **কার্ট — ভেন্ডর অনুযায়ী আলাদা পার্সেলে ভাগ**, প্রতি পার্সেলের নিজস্ব সাব-টোটাল ও ডেলিভারি চার্জ
- কুপন — প্ল্যাটফর্ম-ওয়াইড আর দোকান-নির্দিষ্ট দুই ধরনের
- চেকআউট — তিন ধাপ (ঠিকানা → পেমেন্ট → যাচাই), বিভাগ/জেলা ড্রপডাউন, COD/বিকাশ/নগদ/কার্ড
- অর্ডার — প্রতিটা পার্সেলের আলাদা স্ট্যাটাস টাইমলাইন ও ট্র্যাকিং কোড, পার্সেল আলাদা বাতিল
- উইশলিস্ট, লগইন, রেজিস্ট্রেশন (ক্রেতা / বিক্রেতা দুই ভূমিকা)

**অ্যাডমিন প্যানেল** (`/admin`) — শুধু `is_staff` ইউজারের জন্য

- ড্যাশবোর্ড — GMV, কমিশন, অর্ডার, ক্রেতা, ৭ দিনের চার্ট, আর **"আপনার
  সিদ্ধান্তের অপেক্ষায়"** কার্ড (কতগুলো অনুমোদন/পে-আউট বাকি)
- **দোকান** — অপেক্ষমাণ আবেদন, **NID-র ছবি দেখে অনুমোদন**, স্থগিত/পুনরায় চালু
- **পণ্য** — মডারেশন: প্রকাশ, সরানো, বাতিল
- **অর্ডার** — সব অর্ডার, ভেঙে দেখলে প্রতি পার্সেলের কমিশন ও ভেন্ডরের প্রাপ্য
- **পে-আউট** — টাকা পাঠানোর অনুরোধ, ট্রানজেকশন আইডিসহ পরিশোধিত চিহ্নিত করা
- **ক্যাটাগরি** — যোগ/সম্পাদনা/মুছে ফেলা, উপ-ক্যাটাগরি, ক্রম, চালু-বন্ধ
- **কুপন** — প্ল্যাটফর্ম ও দোকান-নির্দিষ্ট, শতাংশ/নির্দিষ্ট টাকা, মেয়াদ ও সীমা
- **ব্যানার** — হোম পেজের স্লাইডার, লাইভ প্রিভিউসহ
- **ইউজার** — ক্রেতা/বিক্রেতা/স্টাফ, সার্চ, অ্যাকাউন্ট বন্ধ/চালু
- **রিপোর্ট** — সময়সীমা বেছে বিক্রির ধারা, দোকান-ভিত্তিক আয়, সেরা পণ্য,
  ক্যাটাগরি ভাগ, কম স্টক — আর **CSV এক্সপোর্ট** (Excel-এ বাংলা ঠিক দেখায়)
- **সেটিংস** — কমিশন, ডেলিভারি চার্জ, হোল্ড পিরিয়ড কোন নিয়মে চলছে

> রোজকার কোনো কাজের জন্যই Django admin-এ যাওয়ার দরকার নেই। ওটা রাখা
> হয়েছে শুধু অস্বাভাবিক কাজের জন্য — সরাসরি ডেটা সংশোধন বা ডিবাগিং।

**বোঝানোর পাতা** — নতুন ব্যবহারকারী যেন আটকে না যায়

- `/sell` — **দোকান কীভাবে খুলবেন**: ৪ ধাপের গাইড, কী কী কাগজ লাগবে, ক্যাটাগরি
  অনুযায়ী কমিশনের টেবিল, টাকা কবে পাবেন তার টাইমলাইন, স্লাইডার দিয়ে চালানো
  আয়ের ক্যালকুলেটর, আর ৮টি প্রশ্নোত্তর
- `/help` — ক্রেতাদের জন্য: কীভাবে অর্ডার করবেন, “অর্ডার কেন কয়েক ভাগে আসে”
  তার ছবিসহ ব্যাখ্যা, ডেলিভারি চার্জের নিয়ম, রিটার্ন, ৯টি প্রশ্নোত্তর
- হোম পেজে **“কীভাবে কাজ করে”** — ৪ ধাপে পুরো ব্যাপারটা

**ভেন্ডর প্যানেল** (`/vendor`)

- ড্যাশবোর্ড — বিক্রি, অপেক্ষমাণ অর্ডার, ব্যালেন্স, লো-স্টক অ্যালার্ট, ৭ দিনের চার্ট
- পণ্য — তালিকা, সার্চ, যোগ/সম্পাদনা (লাইভ প্রিভিউ ও কমিশন হিসাবসহ), মুছে ফেলা
- অর্ডার — শুধু নিজের পার্সেল, এক ধাপ করে স্ট্যাটাস এগোনো, কমিশন ও প্রাপ্য টাকা
- আয় — লেজার (বিক্রি / কমিশন / রিফান্ড), হোল্ড ব্যালেন্স, পে-আউট ইতিহাস ও অনুরোধ

## ৪. ব্যবসার নিয়ম কোথায়

সব `src/config.js` → `RULES`-এ। বদলাতে চাইলে এক জায়গাতেই:

```js
defaultCommissionRate: 8,          // প্ল্যাটফর্ম কমিশন %
shipping: {
  insideDhaka: 60,
  outsideDhaka: 120,
  extraVendorMultiplier: 0.5,      // ২য় পার্সেল থেকে অর্ধেক চার্জ
  freeShippingThreshold: 2000,     // এর উপরে ওই পার্সেল ফ্রি
},
payoutHoldDays: 7,                 // ডেলিভারির পর টাকা আটকে থাকার সময়
maxQtyPerItem: 10,
pageSize: 12,
```

আর হিসাবের কোড `src/lib/pricing.js`-এ — `calculateCart()`, `shippingForVendor()`,
`applyCoupon()`, `vendorSettlement()`। সবগুলো বিশুদ্ধ ফাংশন, React-এর উপর নির্ভর করে না,
তাই Django-তে হুবহু অনুবাদ করা যায়।

## ৫. ব্যাকএন্ড

**Django ব্যাকএন্ড তৈরি আছে — `backend/` ফোল্ডারে।** সেটআপ ও ব্যাখ্যা
[backend/README.md](backend/README.md)-এ।

```bash
cd backend
.venv\Scripts\python.exe manage.py runserver
```

`.env`-এ `VITE_USE_MOCK=false` থাকলে সাইট ওই API থেকেই ডেটা নেয়;
`true` করলে ব্যাকএন্ড ছাড়াই ডেমো মোডে চলে।

দুইটা সার্ভার একসাথে লাগবে — এক টার্মিনালে Django (পোর্ট ৮০০০),
আরেকটায় `npm run dev` (পোর্ট ৫১৭৩)।

API-র চুক্তি (কোন এন্ডপয়েন্ট কী JSON দেয়) লেখা আছে
[docs/DJANGO_INTEGRATION.md](docs/DJANGO_INTEGRATION.md)-এ।

## ৬. ডিজাইন সিস্টেম

সব টোকেন `src/index.css`-এর `@theme` ব্লকে — একটা হেক্স বদলালেই পুরো সাইটের রং বদলায়।

| ভূমিকা | মান | কোথায় |
|--------|-----|--------|
| ব্র্যান্ড | গভীর এমারাল্ড `#128662` | বোতাম, লিংক, সক্রিয় অবস্থা |
| অ্যাকসেন্ট | উষ্ণ সোনালি `#EDA31D` | অফার, প্রধান CTA |
| কালি | `#10201A` | সব লেখা |
| ক্যানভাস | `#F4F8F6` | পাতার ব্যাকগ্রাউন্ড |
| ভেরিফায়েড | নীল `#1D6FD4` | যাচাই করা ব্যাজ (ব্র্যান্ডের সাথে যেন না মেশে) |

**নীতি:** পাতা প্রায় পুরোটাই নিউট্রাল থাকে, রঙ খরচ হয় শুধু অ্যাকশন আর অবস্থা
বোঝাতে — এতেই ডিজাইন পেশাদার দেখায়।

- **ফন্ট** Anek Bangla (শিরোনাম) + Hind Siliguri (বডি), দুটোই বাংলা-ইংরেজি দুই লিপিতেই চলে
- **এলিভেশন** চার ধাপ: `shadow-xs` → `soft` → `md` → `lift`
- **গাঢ় ব্যাকগ্রাউন্ডের জন্য আলাদা ভ্যারিয়েন্ট** আছে (`variant="onDark"`,
  `tone="gold"`, `tone="glass"`) — `className` দিয়ে রঙ চাপা দিলে Tailwind-এর
  ক্লাস অগ্রাধিকারে হেরে গিয়ে বোতাম অদৃশ্য হয়ে যায়, তাই ওই পথে যাবেন না

### সব ডিভাইসে

| স্ক্রিন | কী বদলায় |
|---------|-----------|
| মোবাইল (< ৬৪০) | নিচে ট্যাব বার, **কার্ট ও পণ্যের পাতায় আটকানো অ্যাকশন বার**, ফিল্টার ড্রয়ারে, টেবিল → কার্ড, ২ কলাম গ্রিড |

| ডেস্কটপ (১০২৪+) | সাইডবার ফিল্টার, স্টিকি অর্ডার সারাংশ, ৪-৫ কলাম গ্রিড, ক্যাটাগরি স্ট্রিপ |

সব পাতা `.container-page` ব্যবহার করে, তাই গাটার সব জায়গায় এক।

## ৭. এখনো যা বাকি

সচেতনভাবে বাদ রাখা হয়েছে, কারণ এগুলোর জন্য ব্যাকএন্ড দরকার:

- আসল OTP পাঠানো ও যাচাই
